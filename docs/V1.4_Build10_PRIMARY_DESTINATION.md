# JI BUS V1.4 Build 10 — 실제 목적지 직행 우선 탐색 수정

## 재현 사례 (2026-11-23)
- 출발: 코오롱하늘채아파트(1151), TAGO 정류장 `CJB270000619`
- 도착: 삼성SDI.에코앤드림(4061), TAGO 정류장 `CJB274000290`
- 과거 대체 하차: 까치말(3037/3036), 별개 정류장
- TAGO 경유 정류장 실제 데이터: 731번(`CJB270026700`)의 하행 운행에서 코오롱하늘채아파트는 67번째, 삼성SDI.에코앤드림은 78번째. 따라서 *정차 순서상 직행 가능*.
- 코오롱하늘채 정류장 경유노선에 731번이 있으며 삼성SDI 정류장 경유노선에서도 731번을 확인함.
- 기존 검색은 즐겨찾기에 저장된 대체 하차 정류장을 목적지 후보에 합쳐 검색하여 잘못된 노선을 먼저 찾을 수 있었음. 초기 6개 노선 제한도 실제 직행 탐색 누락 위험이 있었음.

## 변경 사항
1. 기존 즐겨찾기에 `alt` 필드가 있어도 실제 검색 목적지는 **선택된 `to` 정류장만** 사용한다. 대체 하차 정류장은 검색 후보에 넣지 않음.
2. 즐겨찾기 화면에서 더 이상 사용하지 않는 '대체 하차' 문구를 제거.
3. 기존 즐겨찾기의 `from`, `to`, 제목·순서는 변경하지 않음. `alt` 필드는 호환성을 위해 저장소에 남겨두지만 기능에서는 무시.
4. 새로운 레거시 설정 자동 이관에서는 대체 하차를 새 즐겨찾기로 가져오지 않음. 즐겨찾기 중복 판단도 출발·도착 정류장 조합으로 통일.
5. 초기 검색 시 출발지 경유노선 ID도 조회하여 목적지 경유노선과 교집합을 우선 검사. 노선의 실제 정차 순서는 기존 `stopPairs()`로 검증.
6. 초기 6개 노선 확인에서 직행이 누락될 수 있으므로, 직접적인 경로가 발견되지 않을 경우 최대 24개 후보까지 단계적으로 확인(최대 3개 경로를 찾으면 조기 종료). 사용자 선택형 추가 검색·환승 기능은 유지.
7. API 중계 서버, 기상청 날씨, 사용자의 저장된 즐겨찾기·최근 검색 값은 변경하지 않음.

## 검증
- 실제 TAGO API: 정류장 검색 1151/4061, 양쪽 경유노선 교집합 731번, 경유 정류장 순서 67→78 확인.
- 새 코드·모의 API 테스트: 과거 `alt=까치말`, 실제 `to=삼성SDI`, 우선 후보의 12개 비직행 노선 뒤에 731번을 배치해도 731번 추천 PASS. 까치말의 노선 요청 없음 확인.
- 기존 테스트 포함 15개 파일, 303개 assertion PASS (코드·모의 응답 기준).
- 실제 휴대전화 GPS/도착 예정시간 UAT는 별도 확인 필요.
