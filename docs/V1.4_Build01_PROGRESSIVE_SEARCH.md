## UAT 요구와 설계

기존 검색은 출발·도착 주변 노선을 폭넓게 분석하고, 직행 도착정보가 불명확하면 환승 후보까지 자동 조회해 최초 결과 표시가 늦어졌다.

1. 직접 검색 초기에는 목적지 후보 정류장 최대 2곳의 경유 노선을 확인한 후, 최대 6개 노선 상세를 순차 확인하며 **정방향 직행 1개를 발견하면 즉시 탐색을 멈춘다**. 초기 후보는 전체 노선 중 절대적 최적해가 아니므로 '우선 직행'으로 표시한다.
2. 첫 결과가 나온 뒤 **다른 직행 노선 검색**을 눌러야 남은 목적지 경유 노선을 분석한다.
3. **환승 경로 검색**을 눌러야 출발지 경유 노선까지 분석하고 1회 환승 후보 및 실시간 정보를 가져온다. 직행 노선이 있거나 ETA를 확인할 수 없더라도 환승을 자동으로 호출하지 않는다.
4. GPS 스마트 추천은 목적지 경유노선 최대 12개에서 3개씩 조회하다 직행 후보 발견 시 정지하고, 도착정보는 우선 최대 2개 승차 정류장에서 조회한다. 추천 카드 1개만 표시한다. **다른 직행 추천 검색**을 누르면 최대 20개 노선 및 6개 승차 정류장을 비교해 기존 최대 5개 추천을 표시한다.
5. 검색 중 취소 기능, 방향 판별, 기존 즐겨찾기/최근 검색, GPS 및 날씨, API 키 개인 저장 방식, 15초 실시간 갱신 유지. 노선 상세 요청은 6시간 메모리 캐시를 재사용한다.
6. 검색 범위에 포함되지 않은 노선이 있으므로 결과가 없다는 의미를 '초기 검색 범위 내에서 미발견'으로 구분한다.

## 검증 및 유의사항

- `node --check app.js` 및 `node tests/v14-progressive-search.test.cjs` 실행 권장.
- 기존 `tests/intro.test.cjs`, `tests/v13-dashboard.test.cjs`, `tests/v13-progress.test.cjs`의 V1.4 계약을 수정.
- 브라우저 실제 TAGO API 호출 횟수와 검색 속도는 사용자 단말에서 UAT 필요. 모의 테스트 통과만으로 검색 성능을 보장하지 않는다.
- 추천 노선은 첫 발견한 정방향 직행 후보이며 전체 노선 비교 최적값이 아니다. 필요 시 추가 검색을 실행해야 한다.
- 검색 범위 축소로 일부 직행 후보가 초기 화면에서 제외될 수 있으므로 UAT에서 출퇴근 주요 정류장·동명 정류장·상하행·환승 노선을 확인한다.
