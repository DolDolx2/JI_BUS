## 장애 및 실제 청주시 TAGO 데이터 확인 (2026-11-23)
- 사용자 사례: **삼성SDI → 코오롱하늘채아파트** 검색 시 직행이 없다고 표시.
- TAGO 양방향: `731` (`CJB270026700`).
- 731번 `updowncd=0` 실제 운행 순서: **에코앤드림.삼성SDI(4062, CJB274000291)** 23번째 → **코오롱하늘채아파트(1894, CJB270000924)** 36번째.
- 반대 운행 순서 `updowncd=1`: **코오롱하늘채아파트(1151, CJB270000619)** 67번째 → **삼성SDI.에코앤드림(4061, CJB274000290)** 78번째.
- 사용자 즐겨찾기에 저장된 출발지·도착지가 `4061→1151`인 경우에도, 각 장소의 실제 반대편 정류장 `4062→1894`을 고려하지 않아 검색이 실패했음.

## 수정
1. 초기 직접 검색 단계에서 **출발지와 도착지 모두 양방향 정류장 후보를 자동 확장**. 예전에는 사용자가 '다른 직행 노선 검색'을 누른 뒤에만 일부 확장함.
2. 같은 장소 판정은 명칭을 정규화하고 구분자(`· . , /`) 단위 이름 구성 요소를 정렬해 비교하며, 좌표가 있을 때 **120m 이내** 조건을 추가함. `삼성SDI.에코앤드림` ↔ `에코앤드림.삼성SDI`도 동일 장소로 인식.
3. TAGO 주변 정류장 조회로 반대편의 다른 ID까지 찾아 사용. 이름이 다른 무관한 정류장은 단순히 가깝다는 이유로 검색 후보에 넣지 않음.
4. 실제 직행 후보는 기존 노선의 `updowncd` 방향별 정차 순서 및 탑승 전/하차 후 인덱스를 검사해 확정.
5. 사용자가 저장한 원본 즐겨찾기 출발·도착 ID와 이름, 최근 검색, 네이버지도 도보 길찾기는 변경하지 않음. 직행 안내 카드에서는 실제 탑승할 정류장 ID가 사용됨.
6. 기존 공공 API 중계와 기상청은 변경하지 않음.
